## THE CRITICAL BUGS (would have broken your 2 days)

### 1. The chip would BOOT DEAD in self-clocked mode
- **File:** `rtl/t16_soc.v` (the prescaler block)
- **What was wrong:** The ring-oscillator prescaler (`ro_cnt`) was held at
  zero by reset. In self-clocked mode the CPU clock **IS** `ro_cnt[4]` —
  so during reset the CPU clock froze, and the CPU could never take the
  clock edge it needs to clear its own `halt` flag. After any previous
  halt (or a random power-up state), the chip would never start.
  This is the flagship record-experiment mode.
- **The fix:** The prescaler now free-runs (no reset — simulation starts
  it at 0 for determinism; silicon powers up at a random value, which
  only shifts the phase of a divider — harmless). The reason is written
  as a comment right in the file.
- **Proof:** New TEST 4, Phase B: the CPU computes all 10 Fibonacci
  numbers and halts **with zero external clock edges**. Before the fix,
  Phase B silently "passed" by looking at leftover state — a false
  positive I caught and turned into a real test.

### 2. The P-bit demo made the WRONG DECISION
- **File:** `sw/program_pbit.asm`
- **What was wrong:** The comparison was `SUB` + `BNEZ` → jump-to-turbo
  for **everything except exactly equal**. With SENSOR = 0 (a stone-cold
  chip!) the program shouted TURBO — the opposite of the documented
  intent ("sensor > threshold → turbo").
- **The fix:** A proper signed comparison using the sign-extract trick
  (`SRA` by 15 copies the sign bit down; non-zero = negative = cool →
  eco). The old vs new logic is explained in comments inside the file.
- **Also fixed:** The demo never exercised the WAIT instruction at all —
  the V4-unique sleep feature had ZERO test coverage. The program now
  writes the WAIT register, sleeps in eco mode, wakes on the heartbeat,
  and leaves a "+1 receipt" on GPIO proving it woke up.

### 3. The OpenLane script used the WRONG OpenLane's config format
- **File:** `run_openlane.sh`
- **What was wrong:** It wrote a config with OpenLane **2.x** keys
  (`"pdk::sky130*"`, `"scl::..."`) — your installation is OpenLane
  **1.0.2** (confirmed from your screenshots: `make mount`, `flow.tcl`).
  It also set `DESIGN_NAME: t16_soc` — the simulation configuration —
  which would have put **no ring oscillator in your GDS**.
- **The fix:** Rewritten for OL 1.0.2: `VERILOG_FILES` as a JSON list
  with `dir::` prefix, `FP_SIZING: "absolute"` + `DIE_AREA` (correct
  OL1 syntax — verified against the OL1 docs), top = `t16_top_silicon`,
  and step-by-step instructions matching exactly how you already ran
  OpenLane (`make mount` → `./flow.tcl -design telugu_t16_v4`).

### 4. The ROM could not reach silicon (and could crash the flow)
- **File:** `rtl/t16_rom.v` (+ new `tools/bake_rom.py`)
- **What was wrong:** The ROM only loaded its program with
  `$readmemh(INIT_FILE)`. Inside the OpenLane Docker container that
  relative path does not resolve — Yosys would find no file and the
  GDS would contain an EMPTY (or X) program.
- **The fix:** Two-mode ROM: simulation still uses the `.hex` file
  (nothing changes for you); synthesis uses program words **baked
  directly into the Verilog** between markers, generated by
  `tools/bake_rom.py`. Every word defaults to HALT — even a total
  failure stops the chip safely instead of executing garbage.
- **Proof:** TEST 4 runs the same SoC with `INIT_FILE=""` (pure baked
  mode) — Fibonacci computes correctly from the baked words.

### 5. The synthesis script could never have worked
- **File:** `run_synthesis.sh` + `rtl/t16_ro.v` (one default parameter)
- **What was wrong:** The script passed `-DUSE_RO=0` — but `USE_RO` is a
  *parameter*, not a preprocessor macro, so the flag did nothing. Yosys
  then elaborated `t16_ro` with its own default `USE_RO=1` → sky130
  cells that don't exist in a generic flow → `hierarchy -check` ERROR.
  (I reproduced this exact failure before fixing it.)
- **The fix:** `t16_ro`'s default is now `USE_RO=0` (simulation-safe);
  the silicon tops explicitly pass 1. Verified: real Yosys run completes
  with **0 errors** and writes the netlist.

### 6. The SPICE experiment referenced files that don't exist
- **File:** `spice/ro_vdd_sweep.spice`, `spice/run_experiments.sh`
- **What was wrong:** `.include "sky130_models/nfet_01v8.spice"` — no
  such file exists in V4. The experiment was guaranteed to fail on
  Day 1 afternoon.
- **The fix:** Ported the **proven** transistor lab from the earlier
  package (the one that produced real measured data): bundled real
  SkyWater sky130 tt-corner models + the 3-experiment Python driver
  (VDD sweep / temperature scissors / body-bias Vth) + fresh results.
  The single-point demo deck now includes the correct library path.

### 7. The PDF generator crashed — that's why V4 had no PDF
- **File:** `tools/generate_master_guide_pdf.py`
- **What was wrong:** It used fpdf2's built-in "helvetica" font, which
  is strictly Latin-1 — the guide's bullet `chr(9679)`, `chr(8226)`,
  and every em-dash "—" crashed it with
  `FPDFUnicodeCastException`. The generator had never successfully run
  (there was no PDF in `docs/`). A second crash class
  (`Not enough horizontal space`) came from fpdf2's new `multi_cell`
  cursor behavior.
- **The fix:** Bundled subset Unicode fonts (`tools/fonts/`, built from
  DejaVu, 68 KB total) + registered them in the generator + fixed the
  `multi_cell` cursor returns. The PDF now builds: **31 pages**,
  visually QA'd (cover, tables, code blocks, day plan — all clean).

### 19. CRITICAL: OpenLane would have died at step one (config bug)
- **File:** `run_openlane.sh` (the generated `config.json`)
- **What was wrong:** The config was missing
  `"SYNTH_READ_BLACKBOX_LIB": 1`. Your ring oscillator instantiates two
  REAL sky130 cells (`sky130_fd_sc_hd__inv_2`, `sky130_fd_sc_hd__and2_0`)
  directly in `rtl/t16_ro.v`. OpenLane 1.0.2 does NOT pre-load the cell
  library during synthesis by default (its own default config sets
  `SYNTH_READ_BLACKBOX_LIB 0`), so Yosys would stop at the very first
  `hierarchy -check` with:
  `ERROR: Module 'sky130_fd_sc_hd__inv_2' ... is not part of the design.`
  Tuesday's GDS run would have died before producing anything.
- **How it was proven (both directions):** OpenLane v1.0.2's actual
  synthesis script (`scripts/yosys/synth.tcl` from the v1.0.2 tag) was
  fetched and its EXACT pass order was replayed against this package
  with a real Yosys. Without the flag: the flow fails at hierarchy
  check, exactly as predicted. With the flag: the full sequence
  (hierarchy, flatten, optimize, technology-map) completes with ZERO
  errors and the final netlist still contains ALL 15 inverters + the
  AND gate as real sky130 instances, with the RO prescaler a genuine
  8-bit register (not a constant).
- **Also added:** `"CORE_AREA": "10 10 390 390"` (explicit core inside
  the 400x400 die - OpenLane can auto-compute it, but explicit is one
  less silent variable), and `openlane/README.md` now documents the
  "never delete this line" rule so a hand-rebuilt config cannot lose
  the ring silently.

### 20. run_openlane.sh ignored the exported OPENLANE_DIR
- **File:** `run_openlane.sh`
- **What was wrong:** The script's error message told you to
  `export OPENLANE_DIR=/path` - but the script then overwrote that
  variable with empty string before searching, so the export did
  nothing if OpenLane lived outside the hardcoded search paths.
- **The fix:** `OPENLANE_DIR="${OPENLANE_DIR:-}"` - the exported value
  is now honored first. Verified by running the full script against a
  simulated OpenLane checkout: it finds it, bakes the ROM, copies all
  7 RTL files, and writes the corrected config.json (validated as
  proper JSON).
